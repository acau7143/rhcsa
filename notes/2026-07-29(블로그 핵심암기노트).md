## 2. sudoers / 권한

### NOPASSWD 문법
```
harry ALL=(ALL) NOPASSWD: /usr/bin/passwd
```
- `NOPASSWD:` 뒤에 **반드시 띄어쓰기**
- 명령어 경로는 추측하지 말고 `which 명령어`로 정확히 확인해서 적기 (예: `useradd`는 `/usr/sbin/useradd`, `/bin/useradd`는 존재하지 않는 경로)

### 그룹 전체에 디렉터리 full 권한 (setgid)
> ❗ `chmod 277`은 틀림 — setgid 비트가 빠지고 owner 권한도 깨짐

```bash
# 올바른 방법 (4자리 숫자 모드)
chmod 2770 /해당디렉터리
# 또는
chmod g+s /해당디렉터리
chmod 770 /해당디렉터리
```
| 자리 | 의미 |
|------|------|
| 1번째 (특수비트) | setuid=4, setgid=2, sticky=1 |
| 2번째 owner | 7 = rwx |
| 3번째 group | 7 = rwx |
| 4번째 other | 0 = 없음 |

### ACL — 개인별 vs other 클래스
| 목적 | 명령어 |
|------|--------|
| 특정 유저 1명 | `setfacl -m u:유저명:rwx 파일` |
| 특정 그룹 | `setfacl -m g:그룹명:rwx 파일` |
| 소유자/그룹 제외 나머지 전체(other) | `setfacl -m o::r-- 파일` |

> `o::`는 "개인별 지정"이 아니라 ACL의 **other 클래스**를 바꾸는 것. 개인 지정은 반드시 `u:이름:권한`.

## 3. Cron

```bash
dnf install -y cronie          # crontab 설치 패키지명
crontab -u 유저명 -e            # 특정 유저의 crontab 편집

# 특정 유저만 crontab 사용 허용
echo tom > /etc/cron.allow
```
- `/etc/cron.allow`가 **존재하면** `/etc/cron.deny`는 완전히 무시됨 (allow 우선)
- `at.allow` / `at.deny`도 동일한 로직

## 7. Systemd Timer + Shell Script (RHEL 10 신규 범위)

```bash
vim /usr/local/bin/notify.sh
```
```bash
#!/bin/bash
logger "Time for Break!"
```
```bash
chmod +x /usr/local/bin/notify.sh
```

```ini
# /etc/systemd/system/notify.service
[Unit]
Description=Notify Break Time Service

[Service]
Type=oneshot
ExecStart=/usr/local/bin/notify.sh
```

```ini
# /etc/systemd/system/notify.timer
[Unit]
Description=Notify Break Time Timer

[Timer]
OnCalendar=*-*-* 07:00:00
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
systemctl daemon-reload
systemctl enable --now notify.timer
```

**OnCalendar 작성 요령**
| 표현 | 의미 |
|------|------|
| `Mon *-*-* 07:00:00` | 매주 월요일 오전 7시 |
| `Mon..Fri *-*-* 07:00:00` | 평일 오전 7시 |
| `*-*-* 00/2:00:00` | 매 2시간마다 |
| `*-*-* *:*:00` | 매분 (매시간·매분·0초) |

## 8. Flatpak (신규 범위, 자료 부족)

```bash
useradd student
passwd student

su - student
flatpak remote-add --if-not-exists --user flatdb <제공된 repo URL>
```

## 9. LVM

```bash
# 방식 1 — PE 크기 직접 지정
vgcreate -s 8M wgroup /dev/sdb1
lvcreate -l 50 -n wshare wgroup      # 50 PE × 8MB = 400MB

# 방식 2 — 기본 PE(4MB), 용량 직접 지정
vgcreate vgmyvg /dev/sdb1
lvcreate -n lvmylv -L 1G vgmyvg
```

```bash
# 파일시스템 생성 (경로는 /dev/VG명/LV명)
mkfs.ext4 /dev/wgroup/wshare

mkdir -p /mnt/wshare
echo "/dev/wgroup/wshare /mnt/wshare ext4 defaults 0 0" >> /etc/fstab

systemctl daemon-reload
mount -a
```

## 12. SELinux 포트 + 서비스/방화벽 (커스텀 포트 웹서버)

```bash
# 1. SELinux 포트 라벨 등록
semanage port -a -t http_port_t -p tcp {포트번호}
semanage port -l | grep http_port_t

# 2. httpd 자체가 그 포트를 듣도록 설정 (누락하기 쉬움!)
vim /etc/httpd/conf/httpd.conf
# Listen {포트번호}   ← 추가

# 3. 서비스 + 방화벽
systemctl enable --now httpd
firewall-cmd --permanent --add-port={포트번호}/tcp
firewall-cmd --reload
```

**검증**
```bash
ss -lntp | grep httpd
curl http://localhost:{포트번호}
```

> `curl: Failed to connect... Could not connect to server` = httpd가 그 포트를 아예 안 듣고 있다는 뜻 (SELinux/방화벽 문제 아님).
> `403 Forbidden`이 떠야 SELinux/권한 쪽을 의심.
> DocumentRoot를 기본 경로(`/var/www/html`)에서 안 바꿨다면 `semanage fcontext` + `restorecon`은 불필요.
