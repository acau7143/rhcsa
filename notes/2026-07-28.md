## 1. Root 비밀번호 초기화 (Question 1)

### Question
```
Task: You have forgotten the root password for ServerB.
1. Reset the root password to `secret` to regain access to the system.
2. Ensure that the system boots normally and that SELinux context violations
   do not prevent login.

Aspects/Domains Covered: Operate running systems
(Interrupt the boot process in order to gain access to a system).
```

### My Solution
```
# 1) GRUB 메뉴에서 e 눌러서 편집 모드
# 2) linux 로 시작하는 줄 끝에 추가
rw init=/bin/bash

# 3) Ctrl+X 로 부팅

# 4) bash가 PID1로 뜨면 프롬프트(PS1)가 안 보임 -> 그냥 타이핑
passwd root
# New password: secret / Retype: secret

touch /.autorelabel
exec /sbin/init
```

### Command Option 설명
| 명령/옵션 | 의미 |
|---|---|
| `rw` | 루트 파일시스템을 쓰기 가능하게 마운트 (기본은 `ro`). `/etc/shadow` 수정하려면 필수 |
| `init=/bin/bash` | systemd 대신 bash를 PID1로 직접 실행 → 인증(PAM) 절차 없이 root shell 획득 |
| `touch /.autorelabel` | 다음 정상 부팅 시 SELinux 라벨을 전체 재적용(relabel)하도록 예약. `init=/bin/bash` 상태에서 고친 파일은 SELinux context가 잘못 붙을 수 있어서 필요 |
| `exec /sbin/init` | 현재 셸을 systemd로 교체해서 정상 부팅 이어가기. `reboot`보다 안전 |

### Verification
```bash
getenforce
sestatus
grep -i relabel /var/log/messages | tail
# 로그인 테스트: root / secret
```

### 내가 헷갈렸던 것 / 배운 것
- `init=/bin/bash`로 부팅하면 bash가 PID1이라 `.bashrc` 초기화 과정을 안 거쳐서 **PS1(프롬프트)이 비어있음** → 화면엔 커서만 깜빡이지만 정상 상태, 그냥 타이핑하면 명령이 먹힘.
- 커널 커맨드라인에서 같은 옵션이 중복되면 **뒤에 오는 값이 앞의 값을 덮어씀** → `ro ... rw`면 최종적으로 `rw` 적용됨.
- `touch /.autorelabel`을 빼먹으면 비밀번호는 바뀌어도 SELinux denial로 로그인이 막힐 수 있음.

## 2. 소프트웨어 저장소 구성 (Question 2)

### Question
```
Task: Configure a software repository on ServerB.
1. Mount the provided ISO image `/RHEL-10.iso` to the directory `/repo`.
2. Configure a DNF repository to install packages from the BaseOS and
   AppStream directories within that mount point.
3. Ensure the configuration persists after a reboot (i.e., the ISO is
   mounted automatically).

Aspects/Domains Covered: Manage software (Configure access to RPM repositories),
Configure local storage (Configure systems to mount file systems at boot).
```

### My Solution
```bash
mkdir -p /repo
mv Rocky-10.2-x86_64-dvd1.iso /RHEL-10.iso

# fstab에 등록 (영구 마운트)
echo '/RHEL-10.iso  /repo  iso9660  loop,defaults  0 0' >> /etc/fstab
mount -a

# repo 파일 작성
cat > /etc/yum.repos.d/local.repo << 'EOF'
[BaseOS]
name=BaseOS
baseurl=file:///repo/BaseOS
gpgcheck=0
enabled=1

[AppStream]
name=AppStream
baseurl=file:///repo/AppStream
gpgcheck=0
enabled=1
EOF

dnf repolist
```

### Command Option 설명
| 명령/옵션 | 의미 |
|---|---|
| `mount -o loop` | 일반 파일(ISO)을 블록 디바이스처럼 다루게 하는 옵션. 커널이 loop 디바이스(`/dev/loop0`)를 만들어 파일을 매핑 |
| `iso9660` | CD/DVD·ISO 전용 파일시스템 타입. 태생적으로 read-only라 `defaults`(rw 포함) 옵션 줘도 실제로는 읽기전용으로 마운트됨 |
| fstab 필드 순서 | 장치 / 마운트포인트 / fs타입 / 옵션 / dump / fsck순서 |
| `baseurl=file:///repo/BaseOS` | `file://`(프로토콜, 호스트 없음) + `/repo/BaseOS`(절대경로) → 슬래시 3개 = 빈 호스트 + 절대경로 시작 |
| `gpgcheck=0` | 로컬 연습용 repo라 GPG 서명 검증 생략 (실무에서는 `rpm --import`로 키 등록 후 `gpgcheck=1` 권장) |

### Verification
```bash
mount | grep repo
ls /repo   # BaseOS, AppStream 등 보이는지 확인
dnf repolist
```

### 내가 헷갈렸던 것 / 배운 것
- `iso9660`은 외울 필요 없음 → `file 파일.iso` 명령으로 파일시스템 타입 바로 확인 가능.
- ISO 파일이 업로드 중간에 취소돼서 손상됨(289M만 받아짐) → 재전송으로 해결. 실습 목적(명령어 흐름 익히기)에는 큰 지장 없었음.
- `mv`할 때 절대경로/상대경로 헷갈려서 `/RHEL-10.iso`(손상 파일)와 `~/RHEL-10.iso`(정상 파일)가 따로 존재했던 적 있음 → `ls -lh`로 항상 경로 재확인하는 습관 필요.

## 3. 네트워크 설정 (Question 3)

### Question
```
Task: On ServerB, modify the active network connection to use the following
static settings.
- IPv4: 192.168.1.3/24, Gateway: 192.168.1.1, DNS: 8.8.8.8
- Secondary IPv4: 10.0.0.3/24
- IPv6: fd01::103/64, Gateway: fd01::1
- Secondary IPv6: fd01::200/64
- Ensure these settings are persistent and applied immediately.

Aspects/Domains Covered: Manage Basic Networking
(Configure IPv4 and IPv6 addresses).
```

### My Solution
```bash
# nmtui로 진행 (IPv4/IPv6 각각 <수동>으로 전환 후 주소 입력)

# 참고: nmcli로 하면 이렇게
nmcli connection modify <CONN> \
  ipv4.method manual \
  ipv4.addresses "192.168.1.3/24" \
  +ipv4.addresses "10.0.0.3/24" \
  ipv4.gateway "192.168.1.1" \
  ipv4.dns "8.8.8.8"

nmcli connection modify <CONN> \
  ipv6.method manual \
  ipv6.addresses "fd01::103/64" \
  +ipv6.addresses "fd01::200/64" \
  ipv6.gateway "fd01::1"

nmcli connection up <CONN>
```

### Command Option 설명
| 명령/옵션 | 의미 |
|---|---|
| `ipv4.method manual` | DHCP 대신 static(수동) 방식으로 전환. nmtui에서는 `<자동>` → `<수동>` 드롭다운 변경과 동일 |
| `+ipv4.addresses` | `+` 없이 쓰면 기존 값을 덮어씀. `+`를 붙여야 기존 주소에 "추가"되어 primary/secondary 둘 다 유지됨 |
| `ipv6.method manual` | IPv4와 별개로 IPv6도 따로 수동 전환 필요 (자동으로 안 따라옴) |

### Verification
```bash
ip addr show enp0s3
ip -6 addr show enp0s3
ip route show
nmcli connection show <CONN> | grep -E "ipv4.method|ipv6.method"
```

### 내가 헷갈렸던 것 / 배운 것
- IPv4를 수동으로 바꿨다고 IPv6도 자동으로 수동 전환되는 게 아님 → **각각 따로** 설정 방식(자동/수동)을 지정해야 함.
- nmtui에서 필드가 빨갛게 뜬 게 "내가 172 대역대라서"라고 착각했는데, 실제로는 **문법 오류(포맷 문제)** 때문. nmtui는 실제 네트워크 도달 가능 여부는 저장 시점에 검사하지 않음.
- 접속 중인 인터페이스의 IP를 실제 접속 경로와 다른 대역으로 바꾸면, **적용되는 순간 지금 SSH 세션이 끊기는 게 정상** (호스트와 다른 서브넷이 되어버리기 때문). 이런 작업은 VirtualBox 콘솔에서 직접 하는 게 안전.

## 4. 시스템 시간 및 동기화 (Chrony)

### Question
```
Task: Configure system time and synchronization on ServerB.
1. Set the system timezone to Europe/London.
2. Install and enable Chrony (NTP) to synchronize time.
3. Verify that the system is synchronized ("NTP synchronized: yes").

Aspects/Domains Covered: Deploy, configure, and maintain systems
(Configure time service clients).
```

### My Solution
```bash
timedatectl set-timezone Europe/London
dnf install -y chrony
systemctl enable --now chronyd

# 동기화 안 될 때 강제 보정
chronyc makestep
```

### Command Option 설명
| 명령/옵션 | 의미 |
|---|---|
| `timedatectl set-timezone` | 시스템 타임존 변경. 시스템 시계 자체(UTC)는 안 바뀌고 "보여주는 방식"만 바뀜 |
| `systemctl enable --now` | 서비스 활성화(부팅 시 자동시작) + 지금 즉시 시작을 한 번에 |
| `chronyc sources -v` 표기 | `^*` = 현재 선택된 최적 소스, `Reach`(8진수) = 최근 폴링 응답 성공 여부(377=전부 성공) |
| `chronyc tracking` | 상세 동기화 상태. `Leap status: Normal`이면 정상 |
| `chronyc makestep` | 큰 시간 오차를 즉시 강제로 보정(step). 기본 설정(`makestep 1.0 3`)은 부팅 초반 3번만 자동 step 허용하는데, 그 기회를 넘긴 경우 수동으로 강제 실행 |

### Verification
```bash
timedatectl          # System clock synchronized: yes 확인
chronyc tracking
chronyc sources -v
```

### 내가 헷갈렸던 것 / 배운 것
- `NTP service: active`인데 `synchronized: no`인 상황 발생 → 원인은 VM의 RTC(하드웨어 시계)가 실제 시각보다 18시간 정도 어긋나 있었기 때문. `chronyc tracking`의 `System time: ... slow of NTP time` 값으로 확인.
- chrony는 오차가 크면 기본적으로 천천히 보정(slew)하려 하고, 큰 점프(step)는 부팅 초반 제한된 횟수만 허용 → `chronyc makestep`으로 강제 보정 가능.
- 이건 VM 환경 특유의 문제(재부팅/일시정지 반복으로 RTC 드리프트)라 **실제 시험장에서는 거의 발생하지 않을 상황**으로 판단하고 넘어감.

## 5. 커널 파라미터 - 패킷 포워딩

### Question
```
Task: Configure kernel runtime parameters on ServerB to enable packet forwarding.
1. Enable IPv4 packet forwarding (net.ipv4.ip_forward).
2. Enable IPv6 packet forwarding (net.ipv6.conf.all.forwarding).
3. Ensure both settings persist across reboots.

Aspects/Domains Covered: Operate running systems
(Modify system kernel parameters / Tune systems).
```

### My Solution
```bash
vim /etc/sysctl.d/99-forwarding.conf
```
```
net.ipv4.ip_forward = 1
net.ipv6.conf.all.forwarding = 1
```
```bash
sysctl --system
```

### Command Option 설명
| 명령/옵션 | 의미 |
|---|---|
| `sysctl -w key=value` | 커널 파라미터를 즉시(런타임/휘발성) 적용. 재부팅하면 사라짐 |
| `/etc/sysctl.d/*.conf` | 부팅 시 커널이 자동으로 읽어들이는 영구 설정 파일 위치 (best practice, `/etc/sysctl.conf` 직접 수정보다 권장) |
| `sysctl -p 파일경로` | 지정한 파일 하나만 읽어서 적용 |
| `sysctl --system` | `/etc/sysctl.d/`, `/run/sysctl.d/`, `/etc/sysctl.conf` 등 관련 파일 전체를 우선순위대로 로드 |

### Verification
```bash
sysctl net.ipv4.ip_forward
sysctl net.ipv6.conf.all.forwarding
# 결과: = 1 확인됨
```

### 내가 헷갈렸던 것 / 배운 것
- `sysctl -w`만 하면 재부팅 시 리셋됨 → 파일에 적어두는 것(영구) + `sysctl --system`(즉시 적용) 둘 다 필요.
- `sysctl -p`와 `sysctl --system`은 목적(영구 반영)은 같고 **적용 범위**만 다름 (파일 하나 vs 전체).

## 6. 부팅 메시지 보이게 하기 (rhgb, quiet 제거)

### Question
```
Task: Configure ServerB so that boot messages are visible during startup
(disable the quiet, graphical boot).
1. Remove the `rhgb` and `quiet` parameters from the current kernel's boot options.
2. Ensure this change is persistent and applies to the default kernel.

Aspects/Domains Covered: Operate running systems
(Boot, reboot, and shut down a system normally).
```

### My Solution
```bash
cat /proc/cmdline   # 현재 부팅 옵션 확인
grubby --update-kernel=ALL --remove-args="rhgb quiet"
grubby --info=DEFAULT
```

### Command Option 설명
| 명령/옵션 | 의미 |
|---|---|
| `rhgb` | Red Hat Graphical Boot (부팅 시 스플래시 화면) |
| `quiet` | 부팅 로그 메시지를 화면에 숨김 |
| `grubby --update-kernel=ALL` | 설치된 모든 커널 항목에 적용 (커널이 하나여도 안전하게 ALL 사용) |
| `--remove-args="..."` | 지정한 커널 부팅 옵션들을 제거 |
| `grubby --info=DEFAULT` | 기본으로 부팅되는 커널의 상세 설정(args, root, initrd 등) 출력 |

### Verification
```bash
grubby --info=DEFAULT | grep args
# rhgb, quiet가 없는지 확인
```

### 내가 헷갈렸던 것 / 배운 것
- 이 문제는 실제 RHCSA 덤프에서 자주 보이는 유형은 아니지만, Red Hat 공식 objective("Boot, reboot, and shut down a system normally")에 속하는 스킬(`grubby` 사용법)이라 연습 가치는 있다고 판단.
- Udemy 문제와 블로그 덤프 문제는 결이 다를 수 있음 → 지금 단계(커버리지 채우는 시기)에서는 Udemy로 전체 도메인 훑고, 시험 임박해서 블로그 덤프로 패턴 재확인하기로 결정.

## 7. 로컬 스토리지 구성 (LVM) (Question 7)

### Question
```
Task: Configure local storage on ServerB using the disk `/dev/sdb`.
1. Create a 4GiB partition on `/dev/sdb` and initialize it as a physical volume.
2. Create a volume group named `vgmyvg`.
3. Create a logical volume named `lvmylv` with a size of 1GiB.
4. Format the logical volume with ext4 and mount it persistently at `/lvmylv`.
5. Extend the logical volume by 500MiB and resize the filesystem to match.

Aspects/Domains Covered: Configure local storage
(Create/delete logical volumes, Extend existing logical volumes).
```

### My Solution
```bash
fdisk /dev/sdb
# n(new) -> enter(default) -> enter(default) -> +4G -> w(write)

pvcreate /dev/sdb1
vgcreate vgmyvg /dev/sdb1
lvcreate -n lvmylv -L 1G vgmyvg

mkfs.ext4 /dev/vgmyvg/lvmylv
mkdir /lvmylv
echo "/dev/vgmyvg/lvmylv /lvmylv ext4 defaults 0 0" >> /etc/fstab
mount -a

lvextend -r -L +500M /dev/vgmyvg/lvmylv
```

### Command Option 설명
| 명령/옵션 | 의미 |
|---|---|
| `fdisk` | 디스크 파티셔닝 도구. `n`=새 파티션, `+4G`=크기 지정, `w`=저장 |
| `pvcreate` | 파티션에 LVM 메타데이터를 심어 "Physical Volume"으로 등록 |
| `vgcreate 이름 PV` | PV(들)를 묶어서 Volume Group(저장공간 풀) 생성 |
| `lvcreate -n 이름 -L 크기 VG` | VG에서 지정한 크기만큼 떼어 Logical Volume 생성 |
| `lvextend -L +500M` | LV 용량을 500MiB **추가**(`+` 없으면 절대값으로 덮어씀 - 위험) |
| `lvextend -r` (`--resizefs`) | LV 확장 직후 자동으로 `resize2fs`(ext4) / `xfs_growfs`(xfs) 실행해서 파일시스템도 같이 확장 |

### Verification
```bash
pvs
vgs
lvs
df -h /lvmylv
lsblk
```

### 내가 헷갈렸던 것 / 배운 것
- `lvextend`만 하고 `-r`을 안 붙이면 LV 용량은 커져도 `df -h`상 파일시스템 크기는 그대로임 (그릇은 커졌는데 내용물 인식 못 하는 상태).
- `-L +500M`에서 `+`를 빠뜨리면 "추가"가 아니라 "덮어쓰기"가 되어 용량이 오히려 줄어들 수도 있음 — 실수하면 위험한 부분.
- 스택 구조 순서: 디스크 → 파티션 → PV → VG → LV → 파일시스템. 파티션을 직접 안 쓰고 이렇게 겹겹이 쌓는 이유는 나중에 용량 확장이 훨씬 쉬워지기 때문.

## 8. Shell Script (yes-no.sh)

### Question
```
Task: Create a shell script named `/usr/local/bin/yes-no.sh` on ServerB.
1. The script should accept one argument.
2. If the argument is yes (case-insensitive), output "That is nice".
3. If the argument is no (case-insensitive), output "I am sorry".
4. If the argument is anything else, output "Unknown argument".
5. Make the script executable.

Aspects/Domains Covered: Create simple shell scripts (Conditionally execute code).
```

### My Solution
```bash
vim /usr/local/bin/yes-no.sh
```
```bash
#!/bin/bash
INPUT=$(echo "$1" | tr '[:upper:]' '[:lower:]')

case "$INPUT" in
    yes)
        echo "That is nice"
        ;;
    no)
        echo "I am sorry"
        ;;
    *)
        echo "Unknown argument"
        ;;
esac
```
```bash
chmod +x /usr/local/bin/yes-no.sh
```

### Command Option 설명
| 명령/옵션 | 의미 |
|---|---|
| `tr '[:upper:]' '[:lower:]'` | 입력 문자열의 대문자를 모두 소문자로 변환 |
| `case ... in ... esac` | 값에 따라 분기하는 bash 조건문. `;;`로 각 case 종료 |
| `*)` | case문의 default(나머지 전부) 패턴 |
| (대안) `${1,,}` | bash 4.0+ 파라미터 확장으로 소문자 변환. `tr` 대신 별도 프로세스 없이 처리 가능 |
| `chmod +x` | 실행 권한 부여 |

### Verification
```bash
/usr/local/bin/yes-no.sh Yes     # That is nice
/usr/local/bin/yes-no.sh NO      # I am sorry
/usr/local/bin/yes-no.sh maybe   # Unknown argument
```

### 내가 헷갈렸던 것 / 배운 것
- 문제에 "case-insensitive"라고 명시되어 있으면 반드시 대소문자 처리를 해줘야 함 — `case "$1" in yes)`처럼 원본 그대로 비교하면 `Yes`/`YES` 같은 입력에서 Fail.
- `tr`로 먼저 전부 소문자로 통일한 뒤 비교하는 게, `case`문 패턴에 `[Yy][Ee][Ss]`처럼 대소문자 조합을 다 나열하는 것보다 깔끔함.

### Question


```bash
systemctl enable --now clean-tmp.timer
```

### Command Option 설명
| 항목 | 의미 |
|---|---|
| `Type=oneshot` | 한 번 실행되고 끝나는 서비스라고 systemd에 알림 (계속 떠있는 데몬이 아님) |
| `OnCalendar=daily` | 매일 자정에 실행 (시간 표현식은 `man systemd.time` 참고) |
| `Persistent=true` | 서버가 꺼져있어서 예정 시각을 놓쳤으면, 켜지자마자 즉시 실행 |
| `Unit=` | 이 타이머가 트리거할 서비스 지정 (이름 같으면 생략 가능, 자동 매칭) |
| `WantedBy=timers.target` | 타이머 유닛의 고정 패턴 (일반 서비스의 `multi-user.target`과 대응) |
| `systemctl daemon-reload` | 새/변경된 유닛 파일을 systemd가 인식하게 함 (필수) |

### Verification
```bash

systemctl start clean-tmp.service    # 즉시 1회 테스트 실행
journalctl -u clean-tmp.service
```

### 내가 헷갈렸던 것 / 배운 것
- `Type=oneshot`, `WantedBy=timers.target`, 유닛 파일 위치(`/etc/systemd/system/`)는 **암기 대상** (거의 항상 고정). `OnCalendar=`, `ExecStart=`만 문제마다 이해해서 채워넣으면 됨.

## 13. 아카이브 생성/복원 (Question 17)

### Question
```
Task: Perform archival and restoration on ServerB.
1. Create a bzip2 compressed archive of the `/etc` directory.
2. Save the archive as `/archive/myetc.tbz2`. (Create the directory if needed).
3. Restore the contents of this archive into the directory `/restored/myetc/`.

Aspects/Domains Covered: Understand and use essential tools
(Archive, compress, unpack, and uncompress files using tar, bzip2).
```

### My Solution (처음 시도 - 실패)
```bash

# 에러: tar: /archive/myetc.tbz2: stat할 수 없습니다
```

### My Solution (수정 - 성공)
```bash

tar -cjf /archive/myetc.tbz2 /etc/

mkdir -p /restored/myetc
tar -xjf /archive/myetc.tbz2 -C /restored/myetc/
```

### Command Option 설명
| 옵션 | 의미 |
|---|---|
| `-c` | create — 아카이브 생성 |
| `-x` | extract — 아카이브 풀기 |
| `-j` | bzip2 압축/해제 사용 |
| `-f 파일명` | 대상 아카이브 파일 지정. **묶음 옵션에서 항상 맨 마지막에 와야 함** |
| `-C 디렉터리` | 압축 해제 시 목적지 디렉터리 지정 |

### Verification
```bash
ls -lh /archive/myetc.tbz2
tar -tjf /archive/myetc.tbz2 | head    # 내용물 미리보기
ls /restored/myetc/etc/
```

### 내가 헷갈렸던 것 / 배운 것 (중요 - 실수 직접 겪음)
- **`-cfj`(f가 중간)로 쓰면 실패한다.** `f`는 반드시 인자(파일명)를 받아야 하는 옵션인데, 묶음 안에서 `f` 바로 뒤에 다른 글자(`j`)가 있으면 tar가 그 글자를 **`f`의 파일명 값으로 삼켜버림.** 그 결과 `-f`의 값이 "j"가 되고, 진짜 파일명(`/archive/myetc.tbz2`)은 "아카이브에 넣을 대상 파일"로 오인되어 "그런 파일 없음" 에러 발생.
- **해결: `-cjf`(f를 맨 뒤로)** 또는 `-c -j -f` 처럼 분리해서 사용.
- `tar: 구성 요소 이름 앞에 붙은 '/' 제거 중` 메시지는 에러가 아니라 **정보성 경고** (절대경로를 상대경로로 안전하게 바꿔서 저장한다는 의미).
- 시험에서 `tar -xjf ... -C 목적지` 대신 그냥 풀고 `mv`로 옮겨도 **최종 결과만 같으면 정답 처리됨** (performance-based 시험 특성). 단, `mv` 대상 디렉터리가 이미 존재해야 의도한 구조로 이동됨.

## 원래 상태로 되돌리는 명령어 (Rollback)

```bash
# Q2 - repo/ISO 되돌리기
umount /repo
rm -f /etc/yum.repos.d/local.repo
sed -i '/RHEL-10.iso/d' /etc/fstab

# Q3 - 네트워크는 DHCP로 되돌리려면
nmcli connection modify <CONN> ipv4.method auto ipv6.method auto
nmcli connection up <CONN>

# Q5 - sysctl 되돌리기
rm -f /etc/sysctl.d/99-forwarding.conf
sysctl -w net.ipv4.ip_forward=0
sysctl -w net.ipv6.conf.all.forwarding=0

# Q6 - 부팅 메시지 다시 조용하게
grubby --update-kernel=ALL --args="rhgb quiet"

# Q7 - LVM 되돌리기 (순서 중요: LV -> VG -> PV)
umount /lvmylv
sed -i '/lvmylv/d' /etc/fstab
lvremove /dev/vgmyvg/lvmylv
vgremove vgmyvg
pvremove /dev/sdb1

# Q8 - 스크립트 삭제
rm -f /usr/local/bin/yes-no.sh

# Q10(Q13) - 사용자 정책 되돌리기
rm -f /etc/skel/Note
# login.defs, pwquality.conf는 기본값으로 직접 되돌려야 함 (기본값: PASS_MAX_DAYS 99999, minlen 8)

# Q11(Q15) - ACL 및 테스트 파일 삭제
rm -f /var/tmp/fstab

# Q12(Q16) - systemd 타이머 제거
systemctl disable --now clean-tmp.timer
rm -f /etc/systemd/system/clean-tmp.timer /etc/systemd/system/clean-tmp.service

systemctl daemon-reload

# Q13(Q17) - 아카이브/복원 테스트 산출물 삭제

# Q14(tuned) - 기본 프로파일로 복귀
tuned-adm profile balanced

# Q15(Q19) - SSH 강화 설정 되돌리기 (테스트 계정 정리)

# Q16(Q20) - swap 파티션 되돌리기

# fdisk /dev/sdb 에서 해당 파티션 d(delete)로 제거
```
